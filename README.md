# SHL Conversational Assessment Recommendation System

> A production-ready conversational recommender designed to surface grounded SHL assessment recommendations using retrieval-augmented generation (RAG). Combines semantic search, deterministic ranking, and generative responses for safe, evaluator-ready outputs.

## Project Overview

This project implements a conversational AI assessment recommender built to:

- Provide clarification-driven, evaluator-friendly recommendations for SHL-style assessments.
- Ground all recommendations in an internal SHL catalog to avoid hallucinations.
- Use semantic retrieval (FAISS) and dense embeddings to find relevant catalog items.
- Orchestrate a RAG pipeline with a FastAPI backend and Google Gemini for high-quality natural language responses.

Key goals: safety, traceability, and deterministic fallbacks for evaluation workflows.

## Key Features

- **Conversational Clarification:** The system asks follow-up questions when user intent is ambiguous.
- **Grounded Recommendations:** All recommendations are sourced from the SHL catalog; each suggestion includes provenance.
- **Semantic Search with FAISS:** Dense vector search over catalog embeddings for nearest-neighbour retrieval.
- **Gemini-powered Responses:** Natural, context-aware answers are generated by Google Gemini (configurable via API key).
- **Deterministic Fallback:** When generative confidence is low, the system falls back to a deterministic ranking output.
- **Comparison Handling:** Supports side-by-side recommendation comparisons with scores and evidence.
- **Legal / Off-topic Refusal Handling:** Requests outside allowed scope are refused with safe, explanatory messages.
- **Evaluator-compatible API:** Simple REST endpoints allow batch evaluation and automated scoring pipelines to integrate easily.

## Architecture

High-level components and responsibilities:

- **Catalog Loader** — parses and validates `shl_catalog.json`, normalizes metadata, and exposes records for embedding.
- **Embedding Generation** — uses a sentence-transformer model to convert catalog records and user messages into dense vectors.
- **FAISS Vector Search** — indexes catalog embeddings and performs nearest-neighbour retrieval for semantic grounding.
- **Ranking Engine** — merges retrieval scores, heuristic signals, and business rules to produce a deterministic candidate ranking.
- **Conversation Analyzer** — inspects user messages for intent, slot values, and ambiguity; triggers clarifying follow-ups when needed.
- **Recommendation Orchestration** — composes retrieved evidence, ranking, and fallback logic into a single recommendation object.
- **Gemini Response Generation** — formats grounding context and invokes Gemini to produce the final human-facing response, or emits the deterministic fallback when required.

Architecture flow (simplified):

1. Client sends query to `/chat`.
2. Conversation Analyzer parses intent and decides if clarification is needed.
3. If proceeding, user text is embedded and FAISS retrieves top-k catalog items.
4. Ranking Engine combines semantic scores with heuristics and verification checks.
5. Recommendation Orchestrator prepares grounding context and calls Gemini for a natural response.
6. API returns response plus provenance and ranking metadata.

## Setup

Prerequisites: Python 3.11, Git, and a Gemini API key.

1. Clone the repository

```bash
git clone https://github.com/your-org/shl-assessment-agent.git
cd shl-assessment-agent
```

2. Create and activate a virtual environment

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

3. Install requirements

```bash
pip install -r requirements.txt
```

4. Create a `.env` file from the example and add your Gemini API key

```text
GEMINI_API_KEY=your_api_key
```

5. Run the FastAPI app

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## API Documentation

### GET /health

Returns a basic health status for the service.

Response (200 OK):

```json
{ "status": "ok" }
```

### POST /chat

The `/chat` endpoint accepts a conversation-style payload compatible with evaluator tooling. The request contains a `messages` array where each message has a `role` and `content` field.

Request body (application/json):

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Hiring a senior backend Java engineer with Spring and AWS experience"
    }
  ]
}
```

Response (200 OK): the response model includes a human-facing `reply`, a list of catalog-safe `recommendations`, and an `end_of_conversation` flag. Each recommendation is validated against the API model and contains `name`, optional `url`, and `test_type`.

Example response (realistic):

```json
{
  "reply": "Based on the role description, I recommend the 'Advanced Java Developer Assessment' and the 'Cloud & Infrastructure Aptitude Test'.",
  "recommendations": [
    {
      "name": "Advanced Java Developer Assessment",
      "url": "https://shl.example/tests/adv-java",
      "test_type": "technical"
    },
    {
      "name": "Cloud & Infrastructure Aptitude Test",
      "url": "https://shl.example/tests/cloud-aptitude",
      "test_type": "cognitive"
    }
  ],
  "end_of_conversation": false
}
```

Notes:

- Recommendations are always drawn from the SHL catalog and validated before being returned.
- Google Gemini is used to produce the conversational `reply` when available; a deterministic fallback (the ranked catalog output) is returned if the generator cannot produce a grounded answer.

## Evaluator-focused Notes

- Recommendations are grounded in the SHL catalog and validated before being returned to callers.
- Google Gemini is employed for natural language generation; however, the system always preserves deterministic, catalog-backed fallback recommendations when grounding or LLM confidence is insufficient.
- The API treats requests statelessly for reproducible evaluation; include `messages` to provide context per request.

## Deployment (Render)

Quick steps to deploy on Render:

1. Create a new Web Service on Render and connect the Git repository.
2. Set the build command (optional): `pip install -r requirements.txt`.
3. Set the start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
4. Add environment variables in Render: `GEMINI_API_KEY`.
5. Provision and deploy. Use health checks hitting `/health` for readiness.

Notes:

- Use a Render private service or VPC for production datasets.
- For heavy embedding workloads, add a separate worker or scale instances and persist FAISS index on attached storage.
